# «Посуда GLASS» — план работ: интернет-магазин (вариант B)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Свой интернет-магазин «Посуда GLASS» на основе демо B: каталог, наборы, корзина, оформление с доставкой СДЭК и предоплатой онлайн, заявки «1 клик» и опт, письма владельцу, простая админка. Хостинг и база — в РФ.

**Architecture:**
- Next.js App Router с серверной частью собирается в Docker-образ (`output: "standalone"`).
- База — PostgreSQL в российском облаке: миграции dbmate, запросы через Kysely, RLS по умолчанию запрещает всё.
- Цены и наличие владелец ведёт в Google-таблице. Сайт забирает её раз в час и кладёт в кэш-таблицу `products`. Описания, размеры и габариты лежат в конфиге репозитория.
- Внешние сервисы (СДЭК, платёжный сервис, таблица, почта) спрятаны за интерфейсами. У каждого есть фейк — на нём работают CI и e2e.

**Tech Stack:**
- Next.js 15, React 19, TypeScript, Tailwind 4, shadcn/ui (из демо);
- next-intl, zod, react-hook-form;
- Kysely + pg, dbmate, kysely-codegen;
- jose, bcryptjs, nodemailer, csv-parse, pino;
- Vitest, Playwright;
- GitHub Actions, Timeweb Cloud (Apps + managed PostgreSQL).

**Spec:** `docs/superpowers/specs/2026-11-11-store-b-design.md` (в репозитории демо; в задаче 1 копируется в новый репозиторий как `docs/spec.md`). Читать вместе с этим планом.

## Global Constraints

**Решения по магазину:**
- Только предоплата: картой или СБП на странице платёжного сервиса. Оплаты при получении нет.
- Не делаем: ИИ-администратора, промокоды (механизм выключен), личный кабинет, лояльность, автосоздание отправлений СДЭК, токен WB.

**Цены и тексты:**
- Цену и наличие считает только сервер. Цена из браузера игнорируется.
- Никаких зачёркнутых «старых» цен и выдуманных цифр.
- В названиях нет «SMEG», «Рогашка», «Diamonds». Три доски (WB 963598768, 963704973, 1110279870) на сайт не попадают.
- Обещания (замена разбитого, бесплатная доставка, упаковка) показываются, только если владелец их задал в таблице или подтвердил.

**Данные и безопасность:**
- Хостинг и база — в РФ. Сайт открывается из РФ без VPN.
- Персональные данные:
  - галочка согласия в форме;
  - телефоны в логах через `maskPhone`, имена через `maskName`;
  - никаких персональных данных в URL;
  - никаких персональных данных в публичных репозиториях.
- Правила `~/Desktop/.claude/rules/01-04` действуют полностью. Отступления:
  - PostgreSQL вместо Supabase;
  - миграции dbmate (имена `YYYYMMDDHHMMSS_snake_case.sql`, секции up/down);
  - типы генерирует kysely-codegen в `src/types/database.ts`, обращение `Selectable<DB['orders']>`;
  - `requireRole(['owner'])` читает cookie сессии, без `req`.

**Код:**
- Деньги:
  - в базе — `numeric(12,2)`;
  - в TypeScript — целые копейки `Kopecks` (`src/lib/money.ts`);
  - в интерфейсе — рубли через `formatRub`.
- Строки интерфейса — только в `messages/ru.json`. CI-проверка `check:ru` падает на кириллице в JSX.
- У каждого экрана с данными четыре состояния: скелетон, ошибка с «Попробовать снова» и traceId, объяснённая пустота, контент.

**Значения из спецификации:**
- Статусы заказа (CHECK): `awaiting_payment`, `awaiting_quote`, `paid`, `shipped`, `delivered`, `cancelled`, `returned`.
- Неоплаченный заказ через 24 часа после запроса оплаты получает статус `cancelled`.
- Текст открытки — до 120 знаков.
- Синхронизация с таблицей — раз в час и по кнопке в админке.

**Вёрстка:** ширина 375 px без горизонтальной прокрутки. Стиль и токены — из демо B (`src/app/globals.css`).

**Машина разработчика (Mac, 8 ГБ):**

## Review Focus

1. **Цена или наличие поменялись**, пока покупатель оформлял (владелец правил таблицу). Ожидание: ответ `E.CART_CHANGED` (409) с новыми суммами и списком проблемных позиций; форма показывает новую сумму, заказ не создаётся молча по другой цене. Тест — в задаче 13.
2. **Покупатель вернулся с оплаты раньше уведомления** или нажал «Оплатить» второй раз. Ожидание:
   - `/zakaz/<token>` пишет «Проверяем оплату» и сам обновляется;
   - повторное «Оплатить» отдаёт ту же ссылку на действующий платёж, а не создаёт второй;
   - вторая успешная оплата того же заказа — письмо владельцу «двойная оплата, верните».

   Тесты — в задаче 13.
3. **Владелец испортил таблицу:** переименовал заголовок, очистил лист, ввёл «1 304,00», «Да », неразрывные пробелы. Ожидание:
   - форматы чисел и «да/нет» понимаются;
   - при битом заголовке или если невалидна больше половины строк, синхронизация отменяется целиком: кэш не трогается, владельцу уходит письмо.

   Тест — в задаче 7.
4. **Телефон в любом виде:** «8 928 …», «+7 (928) …», «9281234567», с пробелами и дефисами. Ожидание: приводится к `+7XXXXXXXXXX`; мусор и не-российские номера дают понятную ошибку поля. Тест — в задаче 2.
5. **Виджет СДЭК не загрузился:** нет ключа Яндекс Карт, CDN недоступен, скрипт упал. Ожидание: покупатель видит поле «Город и адрес — рассчитаем доставку сами», заказ оформляется со статусом `awaiting_quote`. Тест — в задаче 14.
